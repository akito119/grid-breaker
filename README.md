# GRID BREAKER DUEL

Python・C++・Javaで盤面を移動するメソッドを作り、相手のトークンを攻撃する2人対戦ゲームです。

ゲーム画面、ルーム管理、勝敗判定はホストPCのNode.jsサーバーが提供します。対戦相手はCloudflare Tunnelで発行したHTTPS URLをブラウザで開くだけで参加できます。プレイヤーコードはホストPC上では直接実行せず、Wandboxへ送信してコンパイル・実行します。

## 必要なもの

ホストPCに以下を用意してください。特定のOSやLinux環境は必要ありません。

- Node.js 20以降（`node`と`npm`を使用します）
- 対応ブラウザ
- インターネット接続（プレイヤーコードをWandboxで実行するため）
- `cloudflared`（インターネット経由で対戦相手へ公開する場合のみ）

サーバーはNode.jsの標準機能だけで動作し、このプロジェクトにnpm依存パッケージはありません。対戦相手は共有URLをブラウザで開くため、Node.jsや`cloudflared`を用意する必要はありません。

## 起動方法

### 1. ゲームサーバーを起動する

ターミナルで、このリポジトリのディレクトリへ移動して起動します。

```bash
cd grid-breaker
npm start
```

既定ではポート`4173`を使用し、<http://localhost:4173/> で開けます。別のポートを使う場合は、`PORT`環境変数を指定して起動してください。

macOS・Linux:

```bash
PORT=3000 npm start
```

Windows PowerShell:

```powershell
$env:PORT=3000; npm start
```

この例では <http://localhost:3000/> で開けます。実際に使用するURLは、起動時にターミナルへ表示されます。

### 2. 外部公開URLを発行する

別のターミナルで次を実行します。

```bash
cloudflared tunnel --url http://localhost:4173
```

ポートを変更した場合は、ここにも同じ番号を指定します。たとえばポート`3000`で起動した場合は次のとおりです。

```bash
cloudflared tunnel --url http://localhost:3000
```

次のようなURLが表示されます。

```text
https://random-name.trycloudflare.com
```

このHTTPS URLをブラウザで開いてください。ルームサーバーURLには同じURLが自動入力されます。

Quick Tunnelはテスト用です。`cloudflared`を再起動するとURLが変わり、PCのスリープ、Node.jsの終了、ネット切断のいずれかで対戦できなくなります。固定URLで運用する場合は、Cloudflareの名前付きTunnelと独自ドメインを使用してください。

## 対戦を始める

### ホスト

1. TunnelのHTTPS URLを開きます。
2. プレイヤー名と部屋設定を入力します。
3. 「ルームを作成」を押します。
4. 表示された共有URLを相手へ送ります。

### 参加者

1. ホストから届いた共有URLを開きます。
2. プレイヤー名を入力します。
3. ルームコードが入力済みであることを確認し、「ルームへ参加」を押します。

参加者側にNode.js、`cloudflared`、コンパイラのインストールは不要です。

## ゲームの進行

各ターンは次の順番で進みます。

```text
壁配置 → メソッド構築 → トークン配置 → 解決
```

- 相手の総HPを先に0にしたプレイヤーが勝利します。
- 最大ターン終了時は残りHPが多いプレイヤーが勝利します。
- 残りHPも同じ場合はサドンデスとなり、先にダメージを与えた側が勝利します。
- HPはターンをまたいで回復しません。
- 各ターン開始時のMPは `最大MP + 最大HP - 現在HP` です。

### 壁配置

両プレイヤーが壁候補を配置します。盤面を分断する候補、重複する候補などはサーバーが不採用にします。確定した壁はメソッドの入力として渡されます。

### メソッド構築

以下の3種類をPython、C++、Javaのいずれかで作成できます。

- 座標指定型: 通過したマスを攻撃し、命中した敵の位置を同じターン中の誘導型へ渡します。
- 誘導型: その時点までに把握した敵トークンの座標と起動済み状態を利用できます。
- 防御型: 通過したマスにいる自分のトークンへ、そのターンだけ有効な軽減を付与します。

MP消費は次の式で計算されます。

```text
ceil(ダメージまたは軽減数 × 言語別に正規化した使用メモリ × emit回数)
```

MPが不足する場合はメソッド全体が不発となり、MPも消費しません。コンパイルエラーや実行時エラーの場合も不発です。

### トークン配置

- トークン数は部屋設定の上限以内にします。
- トークンHPの合計を現在HPと一致させます。
- 各トークンへメソッドと処理順を割り当てます。
- 配置座標は各プレイヤーから見て自陣側へ正規化されます。
- 有効な配置がない場合は、サーバーが既定位置へ全HPを持つトークンを配置します。

### 解決

同じ処理順にある両者のメソッドを比較し、言語差を正規化した実行時間が短い側から解決します。同速の場合は奇数ターンにA、偶数ターンにBを優先します。解決時点でトークンHPが0なら、そのトークンのメソッドは実行されません。

## メソッドへ渡される値

各言語のエディターには雛形が自動入力されます。概念上は次の5つを受け取ります。

| 値 | 内容 |
|---|---|
| `n` | `n × n`盤面の一辺の長さ |
| `walls` | 確定している壁座標の配列 |
| `start` | メソッドを実行するトークンの開始座標 |
| `knownEnemies` | 把握済み敵トークンの座標と`activated`状態 |
| `emit` | 次に移動する隣接座標を出力する関数 |

Pythonでは次の形です。

```python
def act(n, walls, start, known_enemies, emit):
    row, col = start
    emit(row, col + 1)
```

`emit(row, col)`には次の規則があります。

1. 上下左右の隣接マスだけを指定できます。
2. 1回呼ぶごとに出力数が1増えます。
3. 同じマスを複数回通れば、その回数だけ効果と出力数が発生します。
4. 壁または盤外を踏むと、その出力までを数えてメソッドを終了します。
5. 壁衝突前に通過したマスの効果は残ります。
6. 整数以外の座標や隣接していない座標は不正出力です。

## 実行環境

| 言語 | Wandbox環境 |
|---|---|
| Python | CPython 3.13.8 |
| C++ | GCC 13.2.0 / C++20 |
| Java | OpenJDK 21 |

Wandboxは外部サービスです。障害、回線状況、利用制限などによってコードを実行できない場合があります。

```bash
# サーバー起動

npm run smoke
```

## データとセキュリティ

- ルーム状態はホストPCのメモリにのみ保存されます。サーバーを再起動すると全ルームが消えます。
- 共有URLにはルームコードとサーバーURLが含まれますが、プレイヤー操作用の秘密キーは含まれません。
- Quick TunnelのURLを知っている人はサーバーへアクセスできます。友人間のテストではURLを必要な相手だけに共有し、終了後に`cloudflared`を停止してください。
- 現状は小規模な友人対戦向けです。一般公開にはレート制限、ルーム期限、永続ストレージ、監視などの追加が必要です。

## 主なファイル

- `index.html` / `duel.css` / `duel.js` — 対戦画面
- `duel-core.js` — 壁、経路、MP、トークン配置のロジック
- `duel-runners.js` — 3言語のテンプレートと実行ハーネス
- `duel-service.mjs` — ルーム、フェーズ、Wandbox実行、勝敗判定
- `server.mjs` — 静的ファイルと対戦APIを配信するサーバー
- `duel-test.mjs` — ユニットテスト
- `smoke-duel.mjs` — Wandbox結合テスト
